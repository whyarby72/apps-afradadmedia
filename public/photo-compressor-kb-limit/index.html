A simple path from photo to verified file size.

The app keeps the job narrow: choose a JPEG, tell it the size requirement when you know it, and check the real result before you save or share.

01

Choose a JPEG

Select a JPEG/JPG through Android's system photo/document flow. The app reads the current file size and available image dimensions.

02

Set the KB/MB limit

Pick a common target or enter a custom limit. If you do not know the limit, use the separate smaller-copy path without a compatibility promise.

03

Verify the result

For a known target, the app checks the actual output bytes. It reports a truthful result instead of assuming the file will fit.

Built around the upload-size job.

No broad photo-editor feature list. The product focuses on producing a smaller JPEG and making the size outcome clear.

KB

Known limit? Verify it.

Set the target in KB or MB and compare it with the actual output byte size. If the target cannot be reached within the current quality guard, the app reports that honestly.

↓

Don't know the limit?

Create a smaller copy without pretending it is guaranteed to satisfy an unknown website or form requirement.

◉

Core processing stays on-device.

The selected source photo is processed locally for the compression job and is not uploaded to an Afradad Media server for compression.

✓

Original photo preserved.

The normal compression workflow creates a separate result. Save and Share are explicit actions, and the original source is not overwritten.

What the result states — and what it does not.

The app uses distinct result states so a smaller file is not automatically presented as a verified upload-ready file.

PASS / already ready

When a known target exists, the output is checked against the requested byte limit. If the source already meets the limit, unnecessary recompression can be avoided.

Target not met

If the requested target cannot be reached without crossing the current quality guard, the app reports that state instead of making a false success claim.

Reduced

When no upload limit is supplied, the app can make a smaller copy, but it does not claim compatibility with a specific website or form.

JPEG/JPG only

The current product scope supports JPEG/JPG input. Other image formats are not claimed by this release candidate.

Your photo is the job — not the account.

No user account or login is required for the core compression workflow. Read how local photo processing and Google advertising/consent services are separated in the Privacy Policy.

Privacy Policy

Frequently asked questions

Does the app upload my photo for compression?

No. The core compression code processes the selected JPEG on your device and does not upload it to an Afradad Media server for compression.

Does it overwrite the original?

No. The normal workflow preserves the source photo and creates a separate result that you can save or share.

What if I do not know the website's limit?

You can use the smaller-copy path. The app labels that result as reduced rather than claiming that it will meet an unknown requirement.

What image formats are supported?

The current product scope is JPEG/JPG. Support for other formats is not claimed.

Does the whole app work offline?

The core photo-compression job works locally. Advertising and consent services, when included in an ad-enabled release, can require network access.

Are production ads already live?

No claim is made here that production ad serving is already live. The current monetization/privacy candidate still requires final release-artifact reconciliation.
